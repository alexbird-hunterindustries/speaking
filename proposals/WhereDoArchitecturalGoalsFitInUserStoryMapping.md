# Where do Architectural Goals Fit In User Story Mapping?

Jeff Patton's "User Story Mapping" offers a way to visualize your backlog in terms of the user journey, so no work item
is disconnected from the user context it belongs to. With User Story Mapping, we can slice up the work to deliver a
minimal version of the full user experience -- but what about the invisible work that doesn't visibly affect the user?

In this talk, I'll present a two-criteria system for sequencing work which balances technical constraints and customer
goals. We don't want to ignore the architectural goals and build ourselves into a corner. We also don't want to hide in
a cave for months, building invisible (but magnificent) infrastructure and abstractions... with nothing customer-facing
to show for it.

There is a way to model and sequence our work -- inspired by Jeff Patton's User Story Mapping -- which lets us balance (
and communicate about) the tradeoff between architectural responsibility and feature urgency.
